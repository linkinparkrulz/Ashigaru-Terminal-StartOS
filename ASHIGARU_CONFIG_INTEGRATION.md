# Ashigaru Terminal Configuration Integration

## Overview

This document explains how the `.ashigaru/config` file integrates with the Ashigaru Terminal StartOS package, following the same pattern used in the Sparrow Webtop implementation.

## Architecture

### Configuration Flow

```
StartOS UI Config (manifest.yaml)
         ↓
    getConfig.ts (defines UI structure)
         ↓
    setConfig.ts (validates & manages dependencies)
         ↓
    config.yaml (generated by StartOS)
         ↓
docker_entrypoint.sh (reads config.yaml)
         ↓
    .ashigaru/config (JSON config file)
         ↓
    Ashigaru Terminal Application
```

## Key Components

### 1. Configuration Schema (`scripts/procedures/getConfig.ts`)

Defines the user-facing configuration options in the StartOS UI:

- **Ashigaru Settings**
  - `managesettings`: Boolean to enable/disable automatic config management
  - `server`: Union type for Electrum server selection
    - `fulcrum`: Connect to local Fulcrum instance (recommended)
    - `public`: Use public Electrum servers (not recommended)
  - `proxy`: Union type for proxy configuration
    - `tor`: Use StartOS Tor proxy (recommended)
    - `none`: No proxy (not recommended)

### 2. Configuration Validation (`scripts/procedures/setConfig.ts`)

Handles dependency management:
- When `fulcrum` is selected as the server type, it creates a dependency on the Fulcrum service
- Ensures Fulcrum is in "synced" state before allowing the configuration
- Uses the StartOS SDK's `compat.setConfig()` for proper dependency handling

### 3. Default Configuration (`root/defaults/.ashigaru/config`)

A JSON file containing default Ashigaru Terminal settings:
- Server type: `ELECTRUM_SERVER`
- Electrum server: `tcp://fulcrum.embassy:50001`
- Proxy enabled by default
- Theme: `DARK`
- Various wallet and transaction settings

### 4. Docker Entrypoint (`docker_entrypoint.sh`)

The entrypoint script orchestrates the configuration:

1. **Initialization**: Copies default config if none exists
   ```bash
   if [ ! -f /root/.ashigaru/config ]; then
     mkdir -p /root/.ashigaru
     cp /root/defaults/.ashigaru/config /root/.ashigaru/config
   fi
   ```

2. **Configuration Management**: If `managesettings` is enabled:
   - Reads settings from `/root/start9/config.yaml`
   - Updates `.ashigaru/config` using `yq` for JSON manipulation
   - Configures server connection (Fulcrum or Public)
   - Configures proxy settings (Tor or None)

3. **Server Configuration**:
   ```bash
   case "$(yq e '.ashigaru.server.type' /root/start9/config.yaml)" in
   "fulcrum")
     yq e -i '.serverType = "ELECTRUM_SERVER" |
              .electrumServer = "tcp://fulcrum.embassy:50001"' \
              -o=json /root/.ashigaru/config
     ;;
   "public")
     yq e -i '.serverType = "PUBLIC_ELECTRUM_SERVER"' \
              -o=json /root/.ashigaru/config
     ;;
   esac
   ```

4. **Proxy Configuration**:
   ```bash
   case "$(yq e '.ashigaru.proxy.type' /root/start9/config.yaml)" in
   "tor")
     export EMBASSY_IP=$(ip -4 route list match 0/0 | awk '{print $3}')
     yq e -i '.useProxy = true |
              .proxyServer = strenv(EMBASSY_IP) + ":9050"' \
              -o=json /root/.ashigaru/config
     ;;
   "none")
     yq e -i '.useProxy = false' -o=json /root/.ashigaru/config
     ;;
   esac
   ```

## Configuration File Location

- **Default template**: `/root/defaults/.ashigaru/config`
- **Active config**: `/root/.ashigaru/config`
- **StartOS config**: `/root/start9/config.yaml`

## Dependencies

### Fulcrum Integration

When Fulcrum is selected:
- The manifest.yaml defines Fulcrum as an optional dependency
- setConfig.ts creates a runtime dependency requiring Fulcrum to be "synced"
- The entrypoint configures the connection to `fulcrum.embassy:50001`
- Volume mount provides read-only access to Fulcrum data at `/mnt/fulcrum`

### Tor Proxy Integration

When Tor is enabled:
- The entrypoint detects the Embassy gateway IP
- Configures proxy to `<EMBASSY_IP>:9050`
- Ashigaru Terminal routes external connections through Tor

## User Experience

1. User installs Ashigaru Terminal on StartOS
2. User navigates to Config section in the service details
3. User selects Fulcrum or Public server
4. User selects Tor or No proxy
5. On service start/restart:
   - Entrypoint reads user's choices from config.yaml
   - Updates .ashigaru/config accordingly
   - Ashigaru Terminal launches with correct settings

## Manual Configuration

Users can disable `managesettings` to manually edit `.ashigaru/config`:
- Access the service's file system
- Edit `/root/.ashigaru/config` directly
- Restart the service for changes to take effect

## Comparison with Sparrow Webtop

The implementation closely mirrors Sparrow Webtop's approach:

| Aspect | Sparrow Webtop | Ashigaru Terminal |
|--------|----------------|-------------------|
| Config location | `/config/.sparrow/config` | `/root/.ashigaru/config` |
| Server options | electrs, bitcoind, public | fulcrum, public |
| Proxy options | tor, none | tor, none |
| Config format | JSON | JSON |
| Management tool | yq | yq |
| Entrypoint logic | Similar pattern | Similar pattern |

## Benefits

1. **User-Friendly**: Configuration through StartOS UI instead of manual file editing
2. **Safe Defaults**: Sensible defaults that work out of the box
3. **Dependency Management**: Automatic handling of Fulcrum dependency
4. **Flexibility**: Users can still manually configure if needed
5. **Privacy**: Tor proxy enabled by default for external connections

## Technical Notes

- Uses `yq` for YAML/JSON manipulation
- JSON output format (`-o=json`) ensures proper formatting
- In-place editing (`-i`) modifies files directly
- Environment variable substitution (`strenv()`) for dynamic values
- Proper error handling with case statements for unknown values
